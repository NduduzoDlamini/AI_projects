## 📂 Projects

### 1. 🧠 Local AI Health Data Analyst

**Technologies:** Python, Vanna 2.0, Ollama, Qwen, Microsoft SQL Server, ChromaDB, FastAPI, Plotly, pandas

A locally hosted AI data analyst that enables users to explore public health data through natural-language questions. The application combines a language model with SQL Server to discover relevant health indicators, generate read-only SQL queries, retrieve results, and visualize data through interactive charts.

Instead of manually writing SQL queries, users can ask questions about health indicators and use the application to retrieve relevant analytical results.

**Key features**

- **Natural-language analytics:** Ask questions about health indicators using plain English.
- **AI-powered SQL generation:** Use Vanna and a locally hosted Qwen model to support natural-language-to-SQL workflows.
- **Local LLM integration:** Run AI inference using Ollama.
- **SQL Server integration:** Retrieve structured health data from a relational database.
- **Read-only querying:** Designed for analytical queries without modifying source data.
- **Interactive visualizations:** Generate charts using Plotly.
- **Semantic retrieval:** Use ChromaDB for relevant information retrieval and agent memory.
- **API backend:** Use FastAPI to support application functionality.

**Dataset and data source**

The project uses public health data from the World Health Organization (WHO), published through the Humanitarian Data Exchange (HDX).

- **Source:** [HDX – WHO Data for Eswatini](https://data.humdata.org/dataset/who-data-for-swz/resource/4e085174-bbff-4e15-8e23-b1aacaf92cad)
- **Database:** Microsoft SQL Server
- **Table:** `health_indicators`

### 2. 📊 Power BI + Local AI — Natural Language to SQL Data Pipeline

**Technologies:** Power BI, Power Query M, Ollama, Qwen, Microsoft SQL Server

This project explores the integration of a locally hosted language model into a Power BI data analysis workflow. It uses Power Query M to send a natural-language analytical request to a local Ollama endpoint, receive SQL generated by the language model, and use the query to retrieve data from SQL Server for reporting and visualization.

The objective is to combine conversational AI with an established business intelligence workflow while keeping AI inference and database access within the local environment.

**Key features**

- **Natural-language analytics:** Describe a data question in plain English.
- **Local AI integration:** Use Ollama and Qwen to generate SQL.
- **Power Query integration:** Connect Power BI to the local AI endpoint using Power Query M.
- **SQL Server connectivity:** Query structured data for analysis.
- **Automated analytical workflow:** Connect question input, query generation, data retrieval, and Power BI reporting.
- **Privacy-conscious architecture:** Designed to avoid external AI APIs when configured to use only local services.

**Architecture**

1. A user defines an analytical question in Power BI.
2. Power Query M sends the prompt to the locally hosted Ollama service.
3. The language model generates SQL for the requested analysis.
4. SQL Server retrieves the requested data.
5. Power BI loads the results for analysis and visualization.

**Privacy note:** The local-first design depends on the actual Power Query, Ollama, and SQL Server configuration. Review query validation, database permissions, and external connections before using sensitive data.

### 3. 🇸🇿 Eswatini Health Dashboard

**Technologies:** Python, Streamlit, SQL, SQLite, Microsoft SQL Server, Ollama, Qwen, Plotly

**Ask a health question. Get a chart.**

The Eswatini Health Dashboard is an interactive Streamlit application that helps users explore health indicators using plain English instead of manually writing SQL, working through spreadsheets, or navigating data portals.

The application translates questions into analytical queries, retrieves relevant health data, and presents results through interactive charts, headline metrics, and downloadable reports.

🌐 **[Try the live demo](https://ai-health-dashboard.streamlit.app)**

**Key features**

**Natural-language questions**
- Ask questions about health indicators using plain English.
- Generate line, bar, area, pie, and scatter charts, or display results in a table.
- Specify chart types and year ranges in questions.
- Use built-in FAQ entries to guide common analytical requests.
- Fall back to built-in SQL templates when an AI model is unavailable.

**Health trends and visualization**
- Display headline metrics, including totals for yearly counts or the latest values for rates and percentages.
- Compare the first and latest years in a selected period.
- Use configured trend-direction indicators to interpret changes.
- Customize chart types, year ranges, labels, grid lines, chart layouts, and appearance.

**Exports and reporting**
- Download chart data as Excel files.
- Generate AI-assisted reports in Word (`.docx`) and Markdown formats.
- Focus reports on a health topic represented on the dashboard.
- Calculate report figures and changes in application code rather than relying on AI-generated numbers.
- Include data tables in Word reports.

**FAQ management and continuous improvement**
- Save unanswered questions for administrator review.
- Convert unanswered questions into FAQ entries.
- Configure FAQs with indicator codes, chart types, year ranges, and written answers.
- Use matching FAQs to guide responses to similar questions.

**Shared dashboard and access control**
- Allow visitors to add charts to the shared dashboard.
- Restrict chart deletion and administrative configuration to administrators.
- Separate visitor and administrator capabilities.
- Restrict access to SQL details, SQL logs, database settings, and FAQ administration.

**Dataset and data source**

The dashboard uses public WHO health indicator data for Eswatini published through HDX.

- **Source:** [HDX – WHO Data for Eswatini](https://data.humdata.org/dataset/who-data-for-swz/resource/4e085174-bbff-4e15-8e23-b1aacaf92cad)
- **Online database:** Bundled SQLite database containing public health data
- **Local deployment:** Supports Microsoft SQL Server and Ollama when configured appropriately

**Privacy note:** The public demo uses public WHO data and may use a hosted AI model. Do not submit confidential or personal information to the online application. For sensitive data, configure the local deployment to use SQL Server and Ollama, and verify that the application does not send information to external services.

## 🔐 Local AI and Data Privacy

A central theme across these projects is exploring how locally hosted AI can support data analytics without requiring every analytical request to be processed by an external AI service.

The local-first approach combines:

- **Local model inference:** Ollama runs the configured Qwen model.
- **Local data storage:** SQL Server stores structured analytical data.
- **Controlled database access:** Read-only query workflows help reduce the risk of unintended data modification.
- **Local processing:** Questions and results can remain within the local environment when the application is configured exclusively for local services.

Local deployment does not automatically guarantee complete privacy or security. Database permissions, SQL validation, network configuration, application logs, telemetry, and external service settings must be reviewed.

The public Eswatini Health Dashboard demo is separate from a private local deployment and should only be used with non-confidential information.
